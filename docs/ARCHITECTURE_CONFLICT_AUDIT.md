# OAP Architecture Conflict Audit

This is a read-only implementation audit. It does not approve, rename, remove
or activate any architecture component.

## Active canonical result

- One overall-system brain: SMI.
- One heart and approved-action coordinator: Living Kernel.
- Fourteen internal SMI regions; Synthetic Mind is an internal organ and
  Brainstem is a bridge.
- Six distinct OAP Intelligence worlds contain seven families.
- 25 of the locked 78 agent passports are preserved in code; the remaining 53
  identities require an authoritative human-approved roster and are not fabricated.
- Agent anatomy remains Soul–Mind–Body.
- External model providers remain separate from OAP agents and Intelligence
  families.
- Human Authority remains the only final authority.
- No active duplicate system IDs, system names, anatomy roles, agent IDs,
  agent names/aliases or approved agent roles were detected.
- No Kaa identity is registered.

The executable validators are `validate_architecture()`,
`validate_agent_registry()`, `validate_infrastructure_scope()` and
`validate_link_scope()`. Any validation failure suppresses proposed canonical
refinements from the public anatomy view.

## Legacy conflicts isolated from runtime

Historical root-level `app_backup*.py` files and Python files under `backups/`
contain older governance terminology, role sets, database names and routes.
They are preserved for provenance under the upgrade-only rule, but the active
`app.py` does not import them and the SMI bootstrap does not read them.

`OAP_FOUNDATION_MEMORY.md` is explicitly marked as a historical snapshot. Its
older role lists do not create Registry passports, provider assignments,
Builder handlers or SMI region ownership. The active README now uses
Intelligence terminology; the historical `/hrm/council` spelling is documented
only as a legacy compatibility path and is not registered by this slice.

## Decisions still requiring Human Authority approval

1. Decide whether legacy backup applications should move to a separate archive
   outside the deployable source tree. No files were deleted or moved here.
2. Approve any additional agent role or SMI-region assignment after the
   duplicate-role validator passes. No pending role was activated here.
3. Approve each Identity source, provider assignment and Builder handler before
   wiring it to an authenticated operational interface. No public execution
   route was added here.
