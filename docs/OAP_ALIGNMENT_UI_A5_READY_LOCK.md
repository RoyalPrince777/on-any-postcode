# OAP Alignment UI + A5-Ready Boundary Lock

Status: LOCKED
Scope: OAP World, SMI, Living Kernel, Guardian / Aegis, HRM, Green Gate, OAP Atlas, Movement Intelligence, OAP Direct

## Clean UI Rule

OAP screens must separate public product language from private intelligence language.

- Public user surface: OAP World, The Spot, OAP Atlas, The Link, Pulse, Market, Direct.
- Private Founder surface: SMI, Living Kernel, Guardian / Aegis, HRM, Green Gate, War Room, Alignment Intelligence.
- Compatibility routes may remain, but must stay quiet and must not dominate the UI.
- Old checkpoint wording remains internal/compatibility only.

## Alignment Intelligence

Alignment Intelligence is the SMI layer that checks whether a feature fits the OAP organism before it is marked green.

Alignment checks:

1. Correct organ placement.
2. Public/private boundary.
3. Guardian / Aegis safety.
4. HRM receipt requirement.
5. Green Gate evidence state.
6. Founder authority requirement.
7. No fake public claims.
8. No duplicate/noisy system names.

## A5-Ready UI

The UI may show A5 as a locked future state, but it must not enable A5 autonomy.

Allowed UI wording:

- A5-ready
- A5 locked
- A5 proof required
- A5 requires Founder Authority + Guardian + Green Gate + HRM receipts

Not allowed:

- A5 active
- A5 enabled
- fully autonomous execution
- self-approval
- deploy without approval
- payment, dispatch or confirmation authority

## Homepage Cleanup Rule

The homepage should act as a clean OAP World dashboard, not a noisy mixed test board.

It should show:

- OAP World front door.
- OAP Atlas hierarchy.
- Core public systems.
- Founder SMI entry.
- Clean status cards.
- Locked A5 boundary.

It should not show noisy test forms, internal checkpoint language, or unproven live claims as green.

## Final Rule

A5 may be visible as a locked intelligence ambition.
A5 must not be active until proof, safety, governance, receipts and Founder approval are complete.
