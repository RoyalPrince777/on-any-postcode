# OAP OS Android Home Node · bounded readiness gate

The existing **Generation 0** OAP OS public PWA and Termux organism worker
remain independent, first-party components. Android/Linux continues to supply
the phone's kernel and device drivers. This is not a custom ROM, APK or a
replacement operating system.

## Mind · first-party intelligence

Map Intelligence remains the existing first-party road renderer/routing source.
The OAP OS map bridge labels Android **web/PWA hosting**, not native Android
integration or a device certification. Existing SMI/OAP CORE/HRM authorities
are unchanged.

## Body · physical-device evidence

An operator may run the read-only check locally **only after separately
choosing to do so**:

```sh
python scripts/oap_os_home_node_readiness.py
```

It checks the repo HEAD and existence of already-present runtime files without
reading private credentials. It does not start the Termux worker, acquire GPS,
probe the network, change settings or install/update anything. Its Android
classification relies on environment hints and **never certifies actual
hardware**. Absence of evidence means UNKNOWN / not checked.

Physical Android release proof must separately record: actual device and OS
revision, OAP Git revision, install/update/recovery, permission-controlled
location, real OAP-owned road geometry on screen, navigation failure recovery,
source provenance, public/private cache isolation and operator approval.
Do not submit serial numbers, personal GPS traces or database secrets.

## Soul · authority

The separate future **custom Android OS** track requires device support,
bootloader/security/recovery review and explicit new Founder approval.
No Home Node readiness check may modify a device, merge or deploy.
The readiness JSON is descriptive evidence only, never an execution permit.
