- create clean route names
- create compatibility aliases without exposing internal noise
- add read-only status surfaces
- add proof requirements
- add Guardian blocks
- add Green Gate states
- add safe public/private boundary checks
- add HRM receipt requirements

- real-world dispatch

- private media exposure
- A5 autonomy

- external marketplace authority

## Green Gate scoring

A War Room simulation may mark a feature green only when all required proof exists:

1. Route exists.
2. Access boundary is correct.
3. Button or API performs a real safe action or returns a clear locked state.
4. Data source or store exists.
5. Failure is safe.
6. Guardian / Aegis blocks unsafe use.
7. HRM receipt exists for consequential actions.
8. Public claim is accurate and conservative.
9. Founder approval exists for consequential real-world, money, supplier, location or public-claim actions.

If any required proof is missing, the state remains Building, Guarded, Locked or Blocked.
