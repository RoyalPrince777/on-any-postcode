# OAP RTL Proof Slice v0

## Purpose

This is the first synthesizable-style SystemVerilog proof slice beneath the OAP Sovereign Digital SoC software simulator. It is intentionally small. The goal is to prove that the core constitutional boundaries can be expressed and tested in hardware description before any FPGA or ASIC claim is made.

## Included blocks

- Guardian policy boundary for consequential requests.
- 21-gate input contract inherited from the 7 Hardware Trust + 7 Intelligence + 7 Human Authority model.
- Internal NEXUS transmit path and MMIO transmit register.
- Guardian, NEXUS and HRM interrupt state.
- HRM receipt counter and 256-bit receipt/hash register window.
- Protected read-only status/control space.
- Immutable status bits for Guardian enforcing, Human Authority final and real execution disabled.

## Consequential request rule

A consequential request is blocked unless all 21 gate inputs are asserted. A passing request is released only to the internal NEXUS output of this proof slice. There is no external execution output.

This preserves the architecture rule:

**Human Authority -> OAP software -> Guardian policy -> hardware execution**

and does not create a hardware authority path.

## MMIO map

| Address | Register | Access | Purpose |
| --- | --- | --- | --- |
| `0x00` | STATUS | RO | Guardian enforcing, Human Authority final, real execution disabled, last block |
| `0x04` | GATE_STATUS | RO | Current 21 gate inputs |
| `0x10` | NEXUS_TX | WO | Internal-only NEXUS transmit payload |
| `0x14` | NEXUS_COUNT | RO | Internal NEXUS transmit count |
| `0x18` | HRM_COUNT | RO | HRM receipt-event count |
| `0x20..0x3c` | HRM_HASH0..7 | RO | 256-bit HRM receipt/hash window |
| `0x40` | IRQ_STATUS | RO | Guardian/HRM/NEXUS pending bits |
| `0x44` | IRQ_ACK | WO | Interrupt acknowledgement |

Writes to protected read-only status/register space fail closed and raise the Guardian interrupt.

## Testbench proof

The SystemVerilog testbench verifies:

1. Guardian is permanently enforcing.
2. Human Authority is represented as final above this slice.
3. Real execution is permanently disabled.
4. A 20/21 consequential request is blocked.
5. Blocked requests still generate a simulated HRM receipt event.
6. A 21/21 consequential request reaches only the internal NEXUS path.
7. HRM hash registers retain the supplied 256-bit receipt digest.
8. Direct NEXUS MMIO writes remain internal.
9. Protected status writes fail closed and raise Guardian interrupt state.

GitHub CI installs Icarus Verilog, compiles the RTL with SystemVerilog 2012 mode and executes the testbench. A passing run prints:

`OAP_RTL_PROOF_SLICE_V0_PASS`

## Truth boundary

This proof slice does **not** mean:

- an OAP chip has been fabricated;
- an FPGA bitstream has been generated or loaded;
- physical MMIO exists;
- hardware keys or secure boot have been provisioned;
- the HRM hash is generated by a hardware cryptographic engine;
- SMI has become a hardware brain;
- the SoC has independent authority;
- a passing 21-gate request causes a real-world action.

The HRM hash is supplied to the slice as a 256-bit receipt digest and is stored/exposed for integrity-path testing. A dedicated cryptographic engine can be a later RTL milestone.
