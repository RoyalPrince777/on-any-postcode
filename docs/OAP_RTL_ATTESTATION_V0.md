# OAP RTL Trust / Attestation Core v0

## Purpose

This is the third governed SystemVerilog proof slice beneath the OAP Sovereign Digital SoC simulator. It proves that measured-boot evidence, an HRM integrity link, nonce freshness and fail-closed attestation policy can be represented in RTL without granting hardware independent authority.

## Included

- Four write-once measured-boot digest slots per reset epoch.
- An immutable measurement-chain state derived from accepted measurement digests.
- A write-once HRM integrity digest link.
- 128-bit challenge nonce input and replay rejection.
- Attestation-ready and attestation-valid state.
- A deterministic 256-bit simulation proof token linked to the measurement chain, HRM digest and nonce.
- Guardian block latch and violation counter.
- Guardian and attestation interrupt state with explicit acknowledgement.
- Read-only MMIO windows for status, counts, measurement-chain state, proof token and last accepted nonce.
- Protected trust-register writes fail closed.

## Constitutional status

`STATUS` permanently represents:

- Trust / Guardian enforcement active.
- Human Authority final.
- Hardware-backed attestation false in v0.

SMI remains the single Brain. This RTL does not decide policy, approve itself, execute real-world actions or become a second intelligence.

## Measurement rule

Slots 0 through 3 may each be written once between resets. A rewrite attempt:

- does not change the accepted measurement or chain;
- latches Guardian block;
- raises the Guardian interrupt;
- increments the violation counter.

The measurement-chain mixer is for RTL integrity-path testing only. It is **not** a cryptographic hash implementation.

## HRM link rule

The HRM integrity digest may be sealed once per reset epoch. A second write fails closed. This models immutable linkage; it is not a fuse, secure enclave or physical key store.

## Challenge rule

A challenge is accepted only when:

1. all four measurement slots are sealed;
2. the HRM integrity link is sealed;
3. Guardian is not already blocked;
4. the nonce has not already been used in the current reset epoch.

Failure latches Guardian block and does not produce an attestation-valid pulse.

A successful challenge produces a deterministic simulation token from the measurement-chain state, HRM link and nonce. The token is **not a signature** and makes no cryptographic or hardware-backed security claim.

## MMIO map

| Address | Register | Access | Purpose |
| --- | --- | --- | --- |
| `0x00` | STATUS | RO | Trust enforcement, Human Authority, simulation truth, readiness |
| `0x04` | MEAS_COUNT | RO | Accepted measured-boot slot count |
| `0x08` | WRITTEN | RO | Four-slot write-once bitmap |
| `0x0c` | VIOL_COUNT | RO | Fail-closed violation count |
| `0x10..0x2c` | CHAIN0..7 | RO | 256-bit measurement-chain window |
| `0x30..0x4c` | ATTEST0..7 | RO | 256-bit simulation proof window |
| `0x50..0x5c` | NONCE0..3 | RO | Last accepted 128-bit nonce |
| `0x60` | IRQ_STATUS | RO | Guardian / attestation pending bits |
| `0x64` | ATTEST_COUNT | RO | Successful simulation attestations |
| `0x68` | IRQ_ACK | WO | Interrupt acknowledgement |

## Testbench proof

The self-checking testbench verifies:

1. Trust enforcement is active.
2. Human Authority remains final.
3. Hardware-backed attestation remains false.
4. An early challenge fails closed.
5. Four unique measured-boot slots can be sealed.
6. HRM integrity linkage enables attestation readiness.
7. A fresh nonce creates one simulation attestation proof.
8. The proof and nonce are observable through read-only MMIO.
9. Nonce replay fails closed.
10. Measurement-slot rewrites fail closed without changing chain state.
11. Protected trust-register writes fail closed.
12. Guardian interrupt acknowledgement works.

A passing simulation prints:

`OAP_RTL_ATTESTATION_V0_PASS`

## Truth boundary

This proof does **not** mean:

- an OAP chip or FPGA exists;
- secure boot is physically provisioned;
- measurements are generated by hardware;
- a cryptographic hash or signature engine exists;
- hardware keys exist;
- attestation is hardware-backed;
- a remote verifier exists;
- an attestation authorizes a real-world action;
- SMI or the SoC has independent authority.

The next later stage can replace the simulation mixer with a real RTL cryptographic primitive and then verify that separately before any FPGA claim is made.
