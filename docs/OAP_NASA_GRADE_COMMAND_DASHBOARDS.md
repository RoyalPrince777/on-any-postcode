## 1. Master rule

OAP dashboards must feel like a serious command system: clear, fast, calm, beautiful, operational and truthful.

The inspiration is professional mission control: NASA-style telemetry, Google-scale reliability thinking, Apple-clean interface discipline, and lawful emergency coordination structure.

OAP must not imitate or claim classified, military, police, intelligence-agency, emergency-service or government authority powers.

OAP is a civilian, humanitarian-safe, Founder-controlled platform.

Every dashboard must use OAP style:

- 🟢 LIVE: working and checked

- 🛡️ GUARDED: Guardian active

- ✅ CERTIFIED: passed evidence gate

- 🛰️ SOURCE: official external source

## 12. International Humanitarian Emergency Tracker

Purpose: 24-hour global crisis awareness for civilian protection, dignity and safe community response.

This tracker is not military intelligence, not political targeting, not vigilante coordination and not panic broadcasting.

Source classes:

- GDACS for sudden-onset disaster alerts and coordination awareness
- ReliefWeb for humanitarian reports and updates
- USGS for earthquake feeds and event APIs
- official weather/met/national disaster agencies where available
- ACLED only as a governed conflict-data connector where credentials, licence and safe use are approved
- UN/OCHA and official humanitarian sources where available

Dashboard features:

- world crisis map/list
- 24h active events
- new events
- worsening events
- source health
- affected countries
- event type
- severity/alert level
- humanitarian-safe summary
- verified/uncertain label
- safe public guidance
- do-not-share warning where needed
- correction log
- HRM record

Buttons:

- Refresh global signals
- Pull GDACS
- Pull ReliefWeb
- Pull USGS
- Check source health
- Open event
- Mark verified
- Mark uncertain
- Create Safe Signal
- Record to HRM
- Send to War Room
- Export crisis brief
- Block unsafe public post

24h rule:

The tracker should monitor continuously in concept, but the implementation must use safe scheduled checks and source-rate limits. It must not scrape aggressively, overload official services or claim real-time precision when the source is delayed.
