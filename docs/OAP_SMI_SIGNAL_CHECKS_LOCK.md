# OAP SMI Signal Checks Lock

Status: LOCKED
Owner: Human Authority / Founder
Scope: Sovereign Megaverse Intelligence, Command Center, War Room, ISAC, Safe Signals, Global Crisis Tracker, Function Health, Green Gate Board, HRM, Guardian

## Purpose

SMI must check signals before any dashboard feature, crisis item, route, connector, memory claim, or green light is trusted.

Signal checking is not surveillance and not military command. It is civilian-safe verification, source health, public/private boundary review, Guardian protection, and HRM record keeping.

## Master Rule

No signal becomes GREEN unless it has a source, a timestamp, a safety classification, a Guardian boundary, and a proof check.

If the proof is missing, the dashboard must show BUILDING, UNCERTAIN, STALE, LOCKED, or BLOCKED.

## Dashboard Buttons Required

Each major dashboard should include buttons with truthful state:

- Refresh Signals
- Run SMI Signal Check
- Check Source Health
- Check Public/Private Boundary
- Ask Guardian
- Ask War Room
- Record to HRM
- Mark Certified
- Mark Uncertain
- Mark Stale
- Block Unsafe Signal
- Export Safe Brief
- Send to Green Gate

Buttons must either perform a real action, route to a real check, or display LOCKED / BUILDING / NEEDS APPROVAL. They must not pretend to work.

## Signal Status Labels

- LIVE: checked and working
- CERTIFIED: proof passed
- BUILDING: partly implemented
- UNCERTAIN: source or proof incomplete
- STALE: source older than allowed window
- LOCKED: intentionally unavailable until requirements pass
- BLOCKED: unsafe or unauthorized
- PRIVATE: Founder-only
- GUARDED: Guardian boundary active
- NEEDS APPROVAL: Human Authority required

## Crisis Signal Safety

OAP may track world crises for humanitarian awareness, community preparedness, dignity, youth safety, and safe information routing.

OAP must not:
- direct military action
- provide targeting support
- coordinate violence
- expose victims or vulnerable people
- publish panic signals
- claim official emergency authority without legal proof
- turn uncertain reports green

## Green Gate Requirement

A signal is green only when:

1. source exists
2. timestamp exists
3. route/check works
4. public/private boundary is correct
5. Guardian check passes
6. HRM record exists where the signal matters
7. stale-data check passes
8. unsafe claims are blocked
9. the dashboard reflects the true status
