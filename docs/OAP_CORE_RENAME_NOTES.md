# OAP Data / OAP Intelligence naming law

- **OAP Data** is the OAP-facing name for OAP-owned operational/context data.
- **OAP Intelligence** is the OAP-facing name for reasoning, analysis and intelligence capability.
- **OAP CORE** remains the internal canonical runtime/core representation and compatibility boundary.
- `oapdata` is the preferred OAP-facing contract alias where a data key is needed.
- `metadata` is legacy/technical compatibility language only. It must not be presented as an OAP product, intelligence layer or external provider.
- New user-facing copy must say **OAP Data** or **OAP Intelligence**, depending on meaning.
- Realtime transport, signalling, motion and relay infrastructure remain OAP-controlled/first-party. No external realtime provider is required.

Compatibility aliases may remain where removing them would break persisted data, audit schemas or API contracts. They do not define product naming.
